# 隐私与 Git 发布

## 发布边界

源码进入 Git，本地配置与运行状态留在本机。以下内容禁止提交：

- 真实密钥、Token、Cookie、私钥、渠道凭据与账号标识。
- config.json、provider.local.json、本机软件注册表、真实路径与内网地址。
- data、backups、tracker、数据库、日志、恢复记录、历史审计截图和调试资料。
- 指向其他目录的符号链接、子模块及未经审查的二进制文件。

.gitignore 只帮助排除未跟踪文件。即使使用 git add -f，检查脚本也会再次根据暂存路径和内容阻止发布。

## 使用

~~~sh
sh scripts/install-privacy-hook.sh
python3 scripts/check-privacy.py --staged
python3 scripts/check-privacy.py --history
~~~

推送 hook 从 Git 读取拟更新的引用，检查这些引用的完整可达历史，而非仅检查最新差异；已在后续提交删除的秘密仍会被发现。文件路径逐个检查，不因内容与其他安全文件相同而放过私有目录中的别名文件。

脚本仅使用 Python 标准库与 Git，不发网络请求，不自动修改文件，不打印匹配文本。无法解码、文件过大、Git 检查异常或输入不合法时，检查失败并阻止推送。

## 处理命中项

1. 不把匹配值复制到聊天、Issue 或提交说明。
2. 将运行凭据保存在本地忽略配置，源码读取配置；不要使用明文回退值。
3. 重新检查暂存区与完整待推送历史。仅修改最新文件不能清除历史中的内容。
4. 已经对外公开的真实凭据，应由所有者评估并更换；修改 Git 文件不会使旧凭据失效。
5. 处理旧历史、强推或更换凭据前，明确操作范围并保留必要回退材料。

本仓库以干净源码建立新历史。旧仓库已有提交没有被重写；旧历史的敏感内容仍需独立保护，不应将旧仓库整体公开。

## 局限

这是可审查的本地启发式门禁，并非完整 DLP 或专用秘密扫描平台。它不验证凭据是否有效，也不扫描被忽略的本地运行文件。新克隆须安装 hook；本地 hook 可以绕过，因此仍须审查实际发布内容。
